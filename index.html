¿Qué es el Ciclo de Vida del Software (SDLC)?

El SDLC (Software Development Life Cycle) es el marco metodológico utilizado por ingenieros y empresas tecnológicas de todo el mundo para planificar, diseñar, programar, probar y desplegar software de alta calidad sin desperdiciar recursos ni cometer errores costosos.

1

📋 Planificación

Se define el objetivo del negocio, la viabilidad técnica, el presupuesto y los plazos generales.

2

🔍 Análisis de Requisitos

Se recopilan historias de usuario y especificaciones funcionales exactas de los clientes.

3

📐 Diseño del Sistema

Se crean los planos: arquitectura técnica, modelo de datos relacional y prototipos UI/UX.

4

💻 Implementación

Los desarrolladores programan el código real, frontend, backend y lógica de negocio.

5

🧪 Pruebas y QA

Se cazan bugs, se ejecutan pruebas unitarias y de estrés para garantizar la estabilidad.

6

🚀 Despliegue y Soporte

El software sale a servidores de producción (CI/CD) y se monitorea y actualiza continuamente.

¿Cómo se Juega? - Garra HTTP

Una API es como esta máquina de peluches: tú pides una acción con un botón y la máquina te responde al instante.

1 🕹️ ¿Qué quieres hacer?

¿Quieres Obtener (GET), Registrar (POST), Actualizar (PUT) o Eliminar (DELETE)?

2 🎯 Elige la casilla

Cada peluche tiene su casilla (A1, A2, A3...), igual que el número de un locker o ID de registro.

3 🚀 Dale a Enviar

Mira la máquina moverse. Si todo sale bien, verás un mensaje verde de éxito: 200 OK o 201 Creado.

📚 Los 4 Métodos Explicados en 1 Frase:

GET 🔦 Obtener Datos

Obtener Datos (Solo Consultar)

Alumbras el peluche para obtener su nombre y precio. No tocas nada de la máquina ni gastas nada.

Respuesta: 200 OK (¡Lo encontré!) o 404 (¡Casilla vacía!)
POST 📦 Registrar Peluche

Registrar un Nuevo Peluche

Abres la compuerta y registras un peluche nuevo con su información en una casilla libre de la máquina.

Respuesta: 201 Created (¡Peluche registrado con éxito!)
PUT ✨ Actualizar Peluche

Actualizar el Peluche Existente

Actualizas el peluche existente en esa casilla por su versión dorada y brillante de colección.

Respuesta: 200 OK (¡Peluche actualizado!)
DELETE 🦾 Eliminar Peluche

Eliminar Peluche de la Casilla

La garra baja desde el techo, retira el peluche, te lo entrega por la bandeja y deja la casilla vacía.

Respuesta: 200 OK (¡Peluche eliminado!)

Arquitectura REST sobre protocolo HTTP: operaciones CRUD, semántica de idempotencia y códigos de respuesta RFC 9110 para desarrolladores de software.

GET /api/peluches/:id Lectura Segura

Seguro e Idempotente (Safe & Idempotent)

Recupera la representación del recurso. No produce mutaciones de estado en la base de datos ni en el servidor. Puede almacenarse en memoria caché (CDN / Browser).

Status Típico: 200 OK / 404 Not Found
POST /api/peluches Creación de Entidad

No Idempotente (Crea Nuevo Recurso)

Envía un payload JSON en el body para registrar una nueva entidad en la colección. Cada ejecución consecutiva crea un nuevo recurso o genera 409 Conflict si no hay espacio.

Status Típico: 201 Created (Header: Location: /api/peluches/:id)
PUT /api/peluches/:id Reemplazo Total

Idempotente (Actualización de Estado)

Reemplaza por completo el estado del recurso existente por el nuevo payload enviado. Si se ejecuta 1 vez o 100 veces con el mismo body, el estado final del servidor es idéntico.

Status Típico: 200 OK / 204 No Content
DELETE /api/peluches/:id Destrucción de Recurso

Idempotente (Eliminación de Registro)

Elimina el recurso en el backend y libera la clave primaria o casilla. Ejecutar DELETE sobre el mismo ID posteriormente retorna 404 Not Found sin causar fallas.

Status Típico: 200 OK / 204 No Content
